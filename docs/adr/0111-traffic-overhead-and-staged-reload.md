# 0111: Count user traffic once, reload from the staged copy, bound staging

## Status

Accepted

## Context

Three problems were found while investigating "sent and received traffic
in the status bar jumps every time I disconnect and connect":

1. Mihomo counts every byte that crosses TUN. That includes a proxy
   client's own encrypted upstream, which our `PROCESS-NAME` bypass rules
   send DIRECT. Traffic that goes through Hiddify was counted twice: once
   as the app's connection into Hiddify and once as Hiddify's connection
   to its server. On a live host, the `hiddify` DIRECT connections carried
   66 MB while the proxied traffic was 1.6 MB. Each Connect also added
   Hiddify's reconnect and URL-test burst.
2. On Linux the desktop read the overlaid `config.yaml` from
   `/var/lib/iran-split`, which only root can read. Every Live apply
   (pins, the default route, client recovery) failed with `EACCES`.
   Client recovery retried it every 10 seconds.
3. Each attempt staged a new generation and none was removed. The staging
   directory reached 362 directories (388 MB) and kept growing by about
   1 MB every 10 seconds.

## Decision

- `traffic::accumulate` subtracts, per connection, the byte deltas of
  connections whose Mihomo rule is `ProcessName*` with a payload from
  `process_bypass_names` (the same list the config emits). Deltas come
  from lifetime totals, a counter decrease starts a new generation, and an
  unanswered sample keeps the total. A 2-second backend loop samples while
  connected, so hiding the window cannot let short upstream connections
  escape. The store lock is held across the request, because samples
  applied out of order would look like a counter reset.
- On Linux, `reload_core` sends the desktop's own staged
  `runtime/generations/<new id>/config.yaml`. The helper verified its
  SHA-256 and copied it byte for byte into the running workdir. Windows is
  unchanged: its system runtime directory is readable.
- `prune_staged_generations` keeps the four newest UUID-named staging
  directories before a new generation is staged, on both platforms.

## Consequences

The status bar shows traffic generated by apps, not traffic plus the
client's transport overhead. Connections that open and close between
two 2-second samples are counted as user traffic; these are small.
Live applies work on Linux, so recovery stops retrying, and staging stays
bounded even if a future apply keeps failing.
